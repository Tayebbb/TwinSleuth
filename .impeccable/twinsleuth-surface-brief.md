# TwinSleuth practice bench

## Scope and visitor mode

The complete PIN-9 practice flow in `src/web/main.tsx`, including first run, probe selection, evidence review, diagnosis, scoring, and replay. Mode: Operate.

## Audience and task

Technical learners practice diagnosing a simulated industrial fault. They keep plausible causes in view, forecast outcomes for each cause, run tests, cite observations, and defend a diagnosis. The work must remain legible by keyboard and at laptop and phone sizes. Preserve the server-owned truth and forecast privacy, deterministic scoring, Skeptic behavior, and all existing case actions.

## Proof and content

Use the existing PIN-9 arm, controller code, four causes, six probes, revealed observations, and score. Do not introduce causal relationships or forecast details the current model does not support.

## Direction contract

### THESIS

An annotated machine schematic turns each test into a located question, while a separate evidence register keeps prediction and result distinct. The surface refuses the equal-card dashboard arrangement.

### OWN-WORLD

The sheet uses cool drafting stock, dark technical ink, teal for live state, and one signal-amber field for the immediate action. Machine geometry, component labels, and precise callouts carry the character. Controls use square-edged rails and native affordances; type gives the case identity scale while measurements and times stay tabular. No ornamental grid, gradients, or nested containers.

### STORY

The learner reads the arm symptom, tracks plausible faults, selects a probe, commits a forecast, and then sees the observation appended to the evidence ledger. At diagnosis, the learner cites those observations and receives a scored debrief. The visual system must never imply the server-selected fault before evaluation.

### FIRST VIEWPORT

At laptop width, a large machine schematic and safety state anchor the left. The center holds the four-cause register and all six probes. A clearly emphasized right column holds the active probe’s four prediction controls and commit action. The case title and remaining time sit in a compact top line; observed rows span the page below. At phone width, the same order becomes one column: case, schematic, causes, probes, forecast, evidence, diagnosis.
